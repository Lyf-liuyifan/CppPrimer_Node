#### 2.4.3顶层const

​	**1.顶层const:对象本身不可以改变：**

- 定义：const直接修饰变量本身，表示改变量的值无法被修改

  ```cpp
  const int i = 0;//i是顶层const
  ```

- 特点：

  无论变量是什么基本类型，还是指针，只要修饰本身就是顶层const。

**2.底层const：指针/引用指向的对象不可变**（只有指针或引用才有这特性

​	拷入拷出的对象必须拥有相同的底层资格。或者另个对象的数据类型可以相互转换。一般来说，==非常量可以转换成常量==。顶层const的拷贝是不受影响的。值得注意的是：一般是看被拷贝是否是底层const。

```cpp
const int ci = 42;
int i = 0;
i = ci//拷贝ci，因为ci是顶层const所以和普通变量没区别
const int* p2 = &ci;//p2 是底层const
const int* const p3 = p2;
p2 = p3;//底层类型相同，顶层不受影响
int* p = p3;//p3有底层const 所以这条语句是错误的
p2 = p3;//right
p2 = &i;//正确 int* 可以转换成const int*
int& r = ci;//ci有底层所以不行
const int& r2 = i;//可以因为非常量可以转换成非常量
```

​	内联函数和constexpr函数必须的放在头文件当中，因为内敛函数和constexpr函数的本质是在编译时期就进行替换而不是在运行时期通过声明链接到定义。所以这两个函数必须放在头文件当中。

**constexpr函数**
	constexpr函数运行的时候如果传入实参是constexpr表达式，则返回值也是constexpr，也就是说都可以在编译期间计算。但是假如传入的是运行时期计算的东西那么返回值也是。
	这是constexpr函数的特性，即可运行时期，又可以编译时期。

```cpp
constexpr int new_sz(){return 2;}
constexpr int foo = new_sz();//只有返回值也是constexpr声明的才会把函数当成编译时期运行的
```

- constexpr和const最大的区别在于，const仅仅只是声明某个仅可读，而constexpr则声明可以在编译时期运行。

#### 7.5.6字面值常量类

1.什么是constexpr?

​	constexer是用于在编译期间求出结果的表达式、函数或变量。他的目标是：

- 编译时计算
- 类型安全

1.1constexpr变量

- 必须用编译时常量初始化

- ```cpp
  constexpr int MAX = 100; //合法
  constexpr int x = someFunc(); // 不合法
  ```

1.2constexpr函数

- 参数和返回值必须是字面类型（如int,double或自定义字面值类

- 函数体需满足编译时可计算（c++14放宽了限制

- ```cpp
  constepxr int factorial(int n){
  	return (n <= -1) ? 1 : n * factorial(n - 1);
  }
  ```

2.什么是字面值常量类

字面值常量类是可以用于constexpr上下文的类类型，满足以下条件：

1. 所有成员变量均为字面类型。
2. 构造函数必须有一个为constexpr
3. 析构函数必须为默认或constexpr
4. 成员函数没什么要求
5. 构造函数初始化体必须为空

### 7.6类内静态成员

  派生类的作用域是嵌套在基类中的，所以派生类使用基类成员和基类使用基类成员没什么区别，只是注意访问控制符即可。

**继承与静态成员**
  如果基类定义了一个静态成员，那么基类无论有多少个派生类对象，也只会有一个该成员实例。

**被用作基类的类**
  继承的基类不能只有声明，必须得有定义，以为内存模型中，派生类肯定得有基类中的成员才能使用基类成员，这显而易见。

**防止继承发生**
  假如不想要被继承，那我们可以加一个final的关键词

#### 15.2.3 类型转换与继承
派生类对象不能向基类进行类型转换

### 15.3虚函数
**对虚函数的调用可能在运行时才被解析**
  1. 动态绑定只能发生在指针或引用时
  2. 虚函数能动态绑定必须是public继承的时候

**派生类中的虚函数**
  虚函数的要求：
        1. 必须形参类型和个数和基类一致
        2. 返回类型也必须和基类一样，但是有个例外就是假如虚函数返回的是类本身的指针或者引用，则是可行的。

  假如虚函数不想被覆盖则可以加上final关键词

**虚函数与默认实参**
  虚函数的默认实参是谁调用就用谁定义的默认实参，但是最好定义一样的默认实参。

**回避虚函数的机制**
  加基类作用域即可，注意假如派生类调用基类版本的虚函数，但是没加作用域说明符，则会无限循环调用派生类虚函数。

### 15.4 抽象基类
  其实本质上是表示一个某个抽象的概念
**纯虚函数**
  在类内声明时加上'= 0'，一旦一个类有一个纯虚函数，则表示该类是没有实际意义的是过度的抽象类，不能创建对象实例。

### 15.5访问控制与继承
**受保护成员**
  派生类成员或友元，只能通过派生类的对象或在派生类类中对基类protected部分进行访问，不能直接通过基类对象对基类部分进行访问。

**公有、私有和受保护继承**
  基类成员的访问权限会因是什么继承而发生改变(比如原本是public的权限，在private继承后变为在派生类中private权限下的成员)，派生类成员或友元访问基类的权限和什么继承没有关系。
  派生类继承的方式只影响基类成员在派生类中的权限是什么以及派生类用户访问是否能访问基类成员。

**派生类向基类转换的可访问性**
  可访问性是指能不能当做基类来处理，比如假如是public继承，那么类外类内子类都可以把派生类用作基类比如动态绑定，但是假如是protected继承，那么类外是不允许派生类向基类转换的也就是说不能进行动态绑定，只有在派生类或者子类类内中才可行。
  记忆：public->哪里都可以转换，protected->只有自己人（派生类及其子类）看得见，private->只有派生类看得见。

**友元和继承**
 友元关系不能继承，我的朋友不等于儿子的朋友。

**改变个别成员的可访问性**
我们可以通过using声明某个变量以此来改变基类变量在派生类中的权限。比如private继承，基类的成员的权限都会变为private，假如用using来声明变量就可以改变权限，但是原本就为private权限的变量是不能改变的。

### 15.6 继承中的类作用域
**名字冲突与继承**
  派生类可以定义重名变量隐藏基类同名变量，想要使用基类的同名变量得加基类作用域。

**名字查找优先类型检查**
  派生类定义同名函数不会重载基类的同名函数，而是直接隐藏(未被派生类覆盖的同名函数)。即使参数列表不同也会隐藏。但可以通过using引入到派生类中。

### 15.7 构造函数和拷贝控制

#### 15.7.2合成拷贝控制和继承
  基类或派生类的合成拷贝控制成员的行为与其他合成的构造函数、赋值运算符或析构函数累死：他们对类本身的成员依次进行初始化、赋值或销毁的操作。这些合成的成员还负责使用直接基类中对应的操作对一个对象的直接基类部分进行初始化、赋值、销毁。

**派生类中删除的拷贝控制与基类的关系**
  1. 如果基类的拷贝控制、构造函数、析构函数是删除了，那么派生类的也不会有。
  2. 假如基类的移动操作是删除的，或者析构是删除的那也不能用，你想想这些都会导致资源不可释放。

**在构造函数和析构函数中调用虚函数**
  在构造函数中，假如我们的派生类成员还没有定义的时候就使用了派生类的虚函数那么可能会使用派生类成员导致出现未定义错误。所以什么构造函数里析构函数里就用该类的虚函数版本。

#### 15.7.4 继承的构造函数
**继承的构造函数的特点**
假如含有默认形参，那会拆成多个构造函数进行继承。
派生类定义的构造函数也会替换掉继承来的构造函数。

### 15.8 容器与继承
  当我们想要存储派生类对象的话，我们得使用间接存储即存储他们的指针。智能指针也可。

#### 16.2.7转发

---

**补充：**

​	关于完美转发和右值引用很容易混淆

1. 右值引用的本质：

- 右值：临时对象、字面量、或显示通过std::move标记的对象
- 右值引用：通过T&&绑定到右值，表示资源的可移动性，按我的理解就是原本右值是语句结束就销毁的，一旦和右值引用绑定后就代表这个右值和右值变量成了一个可移动的资源。
- 关键特性：

​	右值引用在函数内部会==退化为具名对象==，而具名对象会被视为**左值**。

```cpp
void target(int& x){}
void target(int&& x){}

template <typename T>
void wrapper(T&& arg){
	target(arg);//这里arg是左值不管arg绑定的实参是左值还是右值
}
```

2.std::forward的作用

​	std::forward是有条件的转换工具，仅在参数原始类型是右值时，将其转换成右值引用。意思就是

```cpp
void target(int& x){}
void target(int&& x){}

template <typename T>
void wrapper(T&& arg){
	target(std::forward<T>(arg));//保留右值属性
}
```

- 关键点：

​		std::forward<T>(arg)根据T的推导结果（左值还是右值），**决定**是否将arg转换为右值引用。

```cpp
template <typename T>
T&& forwarding(typename std::remove_reference<T>::type& arg){//std::remove_reference<T>::type是出去T引用的类型
	return static_cast<T&&>(arg);
}
```

1. 依赖类型的定义

- 依赖类型：模板中的某个类型依赖于模板参数T
- 问题：因为编译器在解析模板时，无法直接确定std::remove_reference<T>::type是类型还是其他成员（如静态成员、函数）
